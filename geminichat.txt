Explain open Jarvis repo

OpenJarvis (open-jarvis/OpenJarvis on GitHub) is an open-source, local-first framework for building personal AI agents that run directly on your own hardware, calling cloud APIs only when strictly necessary.   
GitHub

Developed out of Stanford SAIL (Hazy Research and the Scaling Intelligence Lab) as part of their Intelligence Per Watt research initiative, it is licensed under Apache 2.0 and aims to serve as both a research platform and a production foundation for on-device AI.   
GitHub

Core Architecture: The Five Primitives
OpenJarvis is structured around five composable, swappable layers:

Layer	Role	Key Capabilities
1. Intelligence	Model Selection	Manages a catalog of local models and automatically picks the best fit for your specific hardware.
2. Engine	Inference Runtime	Auto-detects your GPU/NPU/CPU and VRAM. Supports 10+ backends—including Ollama, vLLM, SGLang, llama.cpp, MLX, Exo, LiteLLM, and optional cloud providers (OpenAI, Anthropic, Google)—behind a unified interface.
3. Agents	Reasoning & Execution	Ships with 8 built-in agent types operating across three modes: on-demand (simple chat, multi-turn orchestrator), scheduled (cron-based digests), and continuous (long-horizon background monitors).
4. Tools & Memory	Context & Action	Includes built-in web search, code interpreter, calculator, file I/O, local hybrid/BM25 retrieval, persistent SQLite state, and full support for MCP (Model Context Protocol) servers.
5. Learning	Self-Improvement	Captures execution traces from your local interactions to drive automatic improvements to prompts, agent behavior, and model weights (via SFT/GRPO trainers) over time.
Standout Features
Hardware & Energy Awareness: Built specifically to optimize "intelligence per watt," tracking energy usage and cost savings alongside local GPU/Apple Silicon/NPU utilization.   
Jarvis Full Documentation

Interoperable Skills Ecosystem: Follows the agentskills.io open standard and allows you to import thousands of existing community skills directly from repositories like OpenClaw and Hermes Agent.   
GitHub

Multiple Interfaces: Can be used via a CLI (jarvis ask, jarvis digest), a Python SDK (from openjarvis import Jarvis), a browser UI, a native desktop app (macOS, Windows, Linux), or exposed locally as an OpenAI-compatible API (jarvis serve).   
Jarvis Full Documentation

Ready-to-Use Presets: Includes pre-configured workflows such as a Morning Digest (connecting via OAuth to Gmail, Google Calendar, and Tasks), a Deep Research Assistant, a Code Assistant, and a Scheduled Monitor.   
GitHub

jarves vs heremes ai

OpenJarvis (by Stanford SAIL) and Hermes Agent (by Nous Research) are both open-source personal AI agent frameworks, though they are built around different core philosophies and deployment models.

OpenJarvis is a local-first, hardware-aware agent framework designed to run directly on your personal device (laptop/workstation), optimizing for local compute, energy efficiency ("intelligence per watt"), and privacy.

Hermes Agent is a server-first, persistent autonomous agent designed to run continuously on a VPS, home server, or GPU cluster, reaching you across chat platforms while building its own procedural memory and skills over time.

Side-by-Side Comparison
Feature	OpenJarvis	Hermes Agent
Creator	Stanford SAIL (Hazy Research & Scaling Intelligence Lab)	Nous Research
Primary Deployment	On-device / Local-first (MacBook, Linux/Windows workstation)	Server-side / Always-on (VPS, GPU cluster, local server, or serverless)
Core Philosophy	Composable primitives, hardware/energy optimization, and local inference routing	Long-running autonomy, cross-channel messaging, and self-improving workflows
Inference & Models	Auto-detects local GPU/NPU/Apple Silicon and routes across 10+ local engines (Ollama, MLX, vLLM, llama.cpp, etc.); calls cloud APIs only as fallback	Model-agnostic; heavily used with cloud/API routers (OpenRouter, Anthropic, OpenAI) or self-hosted endpoints
Learning & Memory	Captures local execution traces to optimize prompts and fine-tune/align local models (SFT/GRPO) over time	Closed Learning Loop: Reflects after completing tasks and autonomously writes/updates markdown skill files from its own experience
User Interfaces	CLI, Python SDK, Browser UI, native Tauri Desktop App, and local OpenAI-compatible server	Terminal TUI and a multi-channel gateway supporting 20+ messaging apps (Telegram, Discord, Slack, WhatsApp, Signal)
Skills Ecosystem	Uses the agentskills.io open standard and can directly import skills from Hermes Agent and OpenClaw	Native agentskills.io support, official plugins (Home Assistant, Spotify, etc.), plus self-authored skills
Key Differences in Practice
1. Local Hardware Substrate vs. Always-On Chat Assistant
OpenJarvis acts like a programmable chassis for your personal machine. It inspects your local hardware, manages local model weights, tracks latency/energy/cost, and provides a native desktop app and Python SDK for building local workflows.

Hermes Agent acts like a persistent remote employee. You deploy it on a server where it runs cron jobs, executes long-running background tasks (with progress check-ins), and communicates with you wherever you already chat—such as Telegram or Slack.

2. How They "Learn"
OpenJarvis treats learning from a systems/ML perspective: it logs execution traces so you can evaluate agent efficiency and run local post-training (SFT/GRPO) or prompt optimization.

Hermes Agent treats learning from a procedural perspective: after finishing a complex workflow, it enters a reflection step, extracts reusable steps, and writes them into markdown skill files so it handles similar tasks faster and more reliably next time without manual reconfiguration.

3. Interoperability
You don't necessarily have to choose one ecosystem over the other for tooling—both support the agentskills.io standard and MCP (Model Context Protocol), and OpenJarvis can directly import and run community skills built for Hermes Agent.

Which Should You Choose?
Choose OpenJarvis if: You want to run models locally on a Mac or workstation, care about privacy, offline capability, and hardware/energy efficiency, or want a modular Python framework to research and customize local agent architectures.

Choose Hermes Agent if: You want an always-on autonomous assistant running on a server or VPS that you can message from your phone (via Telegram/WhatsApp/Discord), run scheduled cron jobs, and have it autonomously build its own reusable skills over time.

explain in simple english with real world examples

Think of both as personal AI assistants that actually do things on your computer (not just chat), but they live in different places and behave very differently.

The Core Difference in Plain English
OpenJarvis is like a smart, battery-efficient assistant installed directly on your laptop. It runs offline using your own computer’s brain (chip/graphics card), keeps everything private on your device, and watches how much power and memory it uses.

Hermes Agent is like a 24/7 remote employee working on a cloud server. You text it on WhatsApp, Telegram, or Slack while you’re out, and it stays awake all night running tasks and teaching itself new tricks.

Real-World Examples
Example 1: Working on a Flight (No Wi-Fi)
OpenJarvis: You’re on a 6-hour flight with no internet. You ask OpenJarvis to review a folder of code or summarize 50 PDF contracts on your laptop. Because it runs 100% locally on your MacBook or PC, it works seamlessly without Wi-Fi and costs $0 in API fees.

Hermes Agent: Unless you specifically set it up with local models on your laptop, Hermes is typically hosted on a remote server and relies on internet/cloud AI models—meaning it’s built to be reached online rather than offline in airplane mode.

Example 2: Managing Tasks While You're Away From Your Desk
Hermes Agent: You’re at dinner and remember you need a competitor price report by morning. You send a quick message on Telegram or WhatsApp to your Hermes agent. It wakes up on its server, scrapes the websites, builds the report, and texts you back when it’s done.

OpenJarvis: If your laptop lid is closed in your backpack, OpenJarvis is asleep. It is designed to be your personal workstation companion when your device is on, rather than a cloud bot you text from your phone.

Example 3: How They Get Smarter Over Time
OpenJarvis (Hardware & Speed Tuning): Imagine a race car mechanic tuning an engine. OpenJarvis tracks how much battery/electricity and time your laptop spent answering a question, and gradually tunes the underlying AI model so your specific laptop runs faster and uses less power.

Hermes Agent (Writing Its Own Playbook): Imagine a new intern who writes down step-by-step notes after finishing a hard task. The first time you ask Hermes to "clean up my weekly sales CSV and email the chart," it figures out the steps. Afterward, it automatically saves a "How-To Skill" file so next week it does the exact same job in half the time without you explaining it again.

Example 4: Morning Routine
OpenJarvis: At 8:00 AM when you open your laptop, OpenJarvis has already checked your local files, calendar, and emails on your machine and shows a private morning briefing right on your desktop app.

Hermes Agent: At 8:00 AM, Hermes sends a message directly to your phone on Discord or Slack with your daily summary, weather, and updates from overnight background tasks it ran while you slept.

Summary Rule of Thumb
Pick OpenJarvis if you want privacy, offline speed, and zero monthly API bills running right on your personal laptop.

Pick Hermes Agent if you want an always-awake assistant you can text from your phone that runs 24/7 on a server and learns new habits on its own.

If you host Hermes on a cloud VPS, asking it to "dim my screen" or "copy files on my laptop" won't affect your laptop—it only controls the remote server.

To control your personal computer or phone's apps, local files, and screen brightness, you need to run Hermes locally on that specific device (via its terminal CLI, native desktop app, or Termux on Android).

what is the difference then

If both can run terminal commands, manage files, and send messages, the real difference comes down to what happens under the hood, how they are designed to run, and how they improve over time.

Think of it like comparing a custom-tuned sports car built for your driveway (OpenJarvis) versus an autonomous remote worker living in the cloud (Hermes Agent). Both can drive you from A to B, but they were engineered for completely different jobs.

1. Where the "Brain" Runs (Local-First vs. Cloud/Server-First)
OpenJarvis is built for your laptop's hardware: Its entire architecture revolves around making small, free AI models run fast and efficiently on your MacBook or PC without draining your battery or costing API fees. It automatically checks your GPU/CPU, picks the right local engine, and only calls expensive cloud AI (like OpenAI or Claude) when a task is genuinely too hard for your laptop.

Hermes Agent is built for powerful servers: While you can install Hermes on a laptop, it was designed to live 24/7 on a cloud server (VPS) using large, heavy cloud models. It assumes you have fast internet and a big AI brain doing the heavy lifting.

2. How They Behave When You Walk Away
OpenJarvis is a workstation tool: It shines when you are actively working on your computer—indexing your personal notes, summarizing local PDFs in seconds, or running a morning briefing when you open your lid.

Hermes Agent is an always-on remote assistant: Hermes is built around a 24/7 messaging gateway and cron scheduler. You can close your laptop, go out to dinner, and text Hermes on WhatsApp or Telegram to monitor websites overnight, spin up multiple sub-agents in parallel, and ping your phone when a job finishes.

3. How They Learn & Get Smarter
OpenJarvis optimizes speed, cost, and accuracy: OpenJarvis records every task and measures how much time, electricity, and money it took. It uses that data to fine-tune the local model weights or tweak system configurations so your specific computer gets better accuracy for less power.

Hermes Agent writes its own "How-To" playbooks: Hermes focuses on procedural memory. When you walk Hermes through a complicated multi-step chore once, it reflects on what worked and automatically writes a new skill file for itself. Next time, it remembers the exact routine without you having to explain it again.

4. Safety & Guardrails Out of the Box
OpenJarvis locks things down by default: Because it lives on your personal laptop, it starts in a strict sandbox. Out of the box, it won't touch random folders or run broad system commands until you explicitly unlock system access.

Hermes Agent is built for open-ended execution: Hermes is designed to take a complex goal, break it into pieces, delegate tasks to sub-agents, and work directly inside your project directories—making it much stronger at messy, multi-step chores (like digging through 6 months of logs or scraping websites), though it runs slower and requires careful permission setup.

The Bottom Line
OpenJarvis = Best if you want a fast, private, zero-cost AI on your personal computer that excels at searching your local files, running daily briefings, and squeezing maximum performance out of your laptop's hardware.

Hermes Agent = Best if you want an autonomous 24/7 assistant on a server that you control from your phone via chat apps, excels at complex multi-step web and coding chores, and teaches itself new workflows over time.

Yes, you can connect them cleanly—and your split-role design makes a lot of sense. In fact, both frameworks include native protocols built specifically for this kind of handoff.

How the Architecture Works
[Your Voice] ──► OpenJarvis (Local Mic + Whisper STT) ──► Intent Router
                                                              │
       ┌──────────────────────────────────────────────────────┘
       ▼ (Delegates heavy / remote / multi-step work via MCP or HTTP API)
  Hermes Agent (Executes tasks, spawns sub-agents, sends messages/emails)
       │
       ▼ (Returns result)
  OpenJarvis (Speaks reply via local TTS or sends to your phone)
Front-End (OpenJarvis on your laptop): Handles local microphone capture, offline speech-to-text (faster-whisper / whisper.cpp via jarvis chat --voice or its AudioTranscribeTool), quick local lookups, and text-to-speech playback (Kokoro / Cartesia / OpenAI TTS).

Back-End Worker (Hermes Agent on your machine or server): Receives delegated tasks from OpenJarvis, runs complex multi-step workflows, spawns sub-agents, uses its learned skills, and sends emails or chat messages.

Two Ways to Wire Them Together
Option 1: Connect Hermes as an MCP Tool Server (Recommended)
Hermes Agent has a built-in command (hermes mcp serve) that exposes Hermes itself as an MCP (Model Context Protocol) server, and OpenJarvis natively supports connecting to external MCP servers.

How it works: OpenJarvis sees Hermes as a specialized tool (e.g., delegate_to_hermes). When you speak a command to OpenJarvis, its local model decides whether to handle it locally (like "dim my laptop screen") or pass the transcribed request straight to Hermes (like "research these three competitors, write a report, and email it to my team").

Setup overview:

Start Hermes in MCP server mode (hermes mcp serve).

Register that MCP server endpoint in your OpenJarvis configuration.

Add a brief routing instruction in OpenJarvis's system prompt telling it to delegate multi-step research, external messaging, or background jobs to the Hermes MCP tool.
